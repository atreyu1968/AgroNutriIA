Sí. La aplicación puede construirse con **Express, TypeScript y SQLite**, incorporando un **técnico agrícola virtual vinculado a cada finca**. Cada usuario registrará sus propias explotaciones, analíticas, productos disponibles, límites de conductividad y su propia clave de la API de OpenAI.

La arquitectura quedaría así:

# 5. Configuración individual de la API de OpenAI

Cada usuario podrá introducir su propia clave en:

```text
Mi cuenta
└── Integraciones
    └── OpenAI
        ├── Clave API
        ├── Modelo preferido
        ├── Límite mensual
        ├── Máximo por conversación
        └── Prueba de conexión
```

## Seguridad de las claves

La clave:

* Solo se enviará desde el navegador al servidor mediante HTTPS.
* Nunca se utilizará directamente desde React.
* Se cifrará antes de guardarse en SQLite.
* No se devolverá posteriormente al navegador.
* Se mostrará únicamente enmascarada, por ejemplo: `sk-proj-••••••82KQ`.
* Podrá reemplazarse o eliminarse.
* Se descifrará en memoria únicamente cuando se realice una petición.
* No aparecerá en registros, errores ni informes.

El cifrado se realizaría con **AES-256-GCM**, empleando una clave maestra almacenada fuera de SQLite:

```env
API_CREDENTIALS_MASTER_KEY=<clave_maestra_de_32_bytes>
```

Cada credencial tendrá:

* Texto cifrado.
* Vector de inicialización.
* Etiqueta de autenticación.
* Fecha de creación.
* Fecha de última validación.
* Estado.
* Propietario.

No se guardará la clave en texto plano.

Las claves deben mantenerse en un entorno seguro y utilizarse únicamente desde el servidor. La documentación oficial recomienda proteger las claves, rotarlas cuando proceda y asignar los permisos adecuados. ([Plataforma OpenAI][2])

## Configuración por usuario y por finca

La configuración normal será una API por usuario. Además, se podrá establecer una configuración específica para una finca:

```text
Usuario: Francisco Javier
API predeterminada: OpenAI principal

Finca Bajo Cuadras
└── Usar API predeterminada

Finca Los Llanos
└── Usar otra credencial de OpenAI
```

La prioridad será:

1. Configuración específica de la finca.
2. Configuración predeterminada del usuario.
3. Sin IA, si no existe ninguna credencial válida.

El motor de cálculo seguirá funcionando sin OpenAI. Solo se desactivarán el chat y la redacción inteligente.

# 8. Separación entre cálculo agronómico e inteligencia artificial

Este será uno de los principios principales de la aplicación.

## Motor determinista

Responsable de:

* Conversión de unidades.
* Volumen de riego.
* Mezclas de aguas.
* Carga de sodio.
* Carga de cloruros.
* Aporte de boro.
* RAS.
* Carbonato sódico residual.
* Relaciones catiónicas.
* Balance de nutrientes.
* Nitrógeno nítrico, amoniacal y ureico.
* Aportes de Ca, Mg, K, P y S.
* Estimación de conductividad.
* Límites máximos.
* Compatibilidades.
* Fraccionamiento de dosis.
* Alertas.

## Técnico virtual

Responsable de:

* Conversar con el usuario.
* Pedir información ausente.
* Interpretar resultados.
* Comparar campañas.
* Explicar antagonismos.
* Proponer alternativas.
* Justificar recomendaciones.
* Redactar el informe.
* Facilitar la discusión entre agricultor y técnico humano.

La IA no podrá:

* Modificar una analítica sin confirmación.
* Cambiar una abonada validada.
* Aplicar una recomendación automáticamente.
* Superar límites de seguridad.
* Inventar valores que faltan.
* Ocultar que un cálculo es estimado.
* Validar mezclas incompatibles.

# 9. Estado de las recomendaciones

```text

        ↓

        ↓
Validado por el usuario o técnico
        ↓
En aplicación
        ↓
Finalizado
```

La IA únicamente generará **borradores**.

Cuando el técnico virtual proponga una modificación, aparecerá:

```text
Propuesta no aplicada

Sulfato amónico:
Actual: 30 kg/semana
Propuesto: 25 kg/semana

Motivo:
La CE medida supera el límite configurado y el nitrógeno foliar

[Rechazar] [Editar] [Aprobar]
```

La Responses API también dispone de mecanismos para mantener estado conversacional, pero en esta aplicación interesa que la finca conserve su propio registro independiente.

# 14. Modelo principal de SQLite

```prisma
model User {
  id                 String              @id @default(cuid())
  email              String              @unique
  passwordHash       String
  name               String
  isActive           Boolean             @default(true)
  apiCredentials     ApiCredential[]
  memberships        FarmMembership[]
  ownedFarms         Farm[]              @relation("FarmOwner")
  conversations      FarmConversation[]
  createdAt          DateTime            @default(now())
  updatedAt          DateTime            @updatedAt
}

model ApiCredential {
  id                 String    @id @default(cuid())
  userId             String
  provider           String    @default("openai")
  name               String
  encryptedSecret    String
  initializationVector String
  authTag            String
  selectedModel      String
  monthlyLimit       Decimal?
  isDefault          Boolean   @default(false)
  isActive           Boolean   @default(true)
  lastValidatedAt    DateTime?
  user               User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  farmOverrides      FarmApiConfiguration[]
  createdAt          DateTime  @default(now())
  updatedAt          DateTime  @updatedAt
}

model Farm {
  id                 String              @id @default(cuid())
  ownerId            String
  companyName        String?
  name               String
  island             String?
  municipality       String?
  surfaceHa          Decimal?
  owner              User                @relation("FarmOwner", fields: [ownerId], references: [id])
  memberships        FarmMembership[]
  plots              Plot[]
  apiConfiguration   FarmApiConfiguration?
  conversations      FarmConversation[]
  createdAt          DateTime            @default(now())
  updatedAt          DateTime            @updatedAt
}

model FarmMembership {
  id                 String   @id @default(cuid())
  farmId             String
  userId             String
  role               String
  farm               Farm     @relation(fields: [farmId], references: [id], onDelete: Cascade)
  user               User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([farmId, userId])
}

model FarmApiConfiguration {
  id                 String        @id @default(cuid())
  farmId             String        @unique
  credentialId       String
  farm               Farm          @relation(fields: [farmId], references: [id], onDelete: Cascade)
  credential         ApiCredential @relation(fields: [credentialId], references: [id], onDelete: Cascade)
}
```

El esquema completo incorporará además analíticas, riegos, mezclas de agua, cultivos, fertilizantes, recomendaciones, informes y auditoría.
